# PRD

Живой документ требований. Обновлён под **OSS personal bot** (без billing).

## Текущий scope

### Формат

Self-hosted Telegram-бот. Один инстанс на владельца; доступ по allowlist (опционально).

### Входные данные (фаза 1)

- Вставленный текст
- URL страницы

### Входные данные (фаза 2 — не в текущем scope)

- Скриншоты / изображения

### Выходные данные

После загрузки документа пользователь выбирает режим кнопками:

1. **Объяснение простым языком**
2. **Важные / рискованные пункты**

Тон: **нейтральный**. Бот не рекомендует соглашаться или отказываться.

### UX-модель

Document-centric архитектура.

Поток:

1. Пользователь создаёт **новый документ**
2. Отправляет текст и/или URL
3. Бот собирает clean text (ingest)
4. Бот подтверждает готовность и предлагает кнопки анализа
5. Результаты кэшируются в БД

Правила:

- Новые документы создаются **явно**
- История документов сохраняется
- **Нет платных проверок** — владелец платит только за LLM API у своего провайдера

### Доступ

- `ALLOWED_TELEGRAM_IDS` — comma-separated Telegram user IDs
- Пустой список = бот публичный (security warning при старте)
- Неразрешённые пользователи получают отказное сообщение

### Критерии успеха (для self-host)

- Бот стабильно работает на SQLite без отдельного DB-сервера
- Настройка за минуты: `.env` + `go run ./cmd/telegram`
- Понятные ответы на реальных Terms/Privacy

## Пользовательские сценарии

### Основной

1. Пользователь видит Terms / Privacy / popup
2. Открывает бота, создаёт документ
3. Вставляет ссылку или текст
4. Нажимает **Объяснить просто** или **Подсветить риски**
5. Читает результат и решает

### Новый документ

Явная команда / кнопка **Новый документ** — предыдущий остаётся в истории.

## Требования

### Функциональные

- Явное создание документа
- Приём текста и URL
- Ingest → clean text (LLM + URL fetch)
- Кнопки анализа после ingest
- Кэш результатов анализа
- История документов на пользователя
- Telegram allowlist
- `/demo` — статичный пример

### Нефункциональные

- SQLite, файл по `DATABASE_PATH`
- LLM: OpenAI-compatible HTTP API; invalid JSON → 1 retry
- i18n UI по locale Telegram; анализ на языке пользователя
- Тесты обязательны для core и storage
- Docker-образ для деплоя

### Модель анализа

**Ingest:** первый LLM-вызов (или URL fetch + LLM) → clean text в БД.

**Analysis:** по кнопкам, lazy + cache; повтор того же режима — из БД.

## Ограничения

- Нет production SLA — personal/self-hosted
- Скриншоты не в фазе 1
- Нет follow-up Q&A с документом

## Non-goals

- Монетизация, пакеты проверок, payment providers
- Юридические советы
- Универсальный legal analyzer как позиционирование

## Запланированные расширения

- Скриншоты / изображения
- Уточняющие вопросы по документу
- Дополнительные режимы анализа
- Web UI (тот же core)
